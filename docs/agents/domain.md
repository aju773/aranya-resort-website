# Domain docs

This project uses a single-context layout: `CONTEXT.md` and `docs/adr/` at the repository root.

## Before exploring

- Read `CONTEXT.md` when present.
- Read ADRs in `docs/adr/` relevant to the work.
- If these files are absent, proceed silently. Do not create placeholder domain documents solely for setup.

## Terminology and decisions

Use established glossary terms in specifications, tickets, implementation, and tests. If a needed term is missing, flag the gap rather than silently inventing competing terminology.

Flag conflicts with existing ADRs explicitly and identify the affected decision before proposing a replacement.
